# GitHub 备份范围与恢复说明

## 公开镜像完成情况

此仓库提供的只是**安全筛查后的部分研发资产**，并非项目完整备份，也不能恢复原始 APK、账号数据库或签名工具链。

已备份（GitHub 提交可核验）：
- 项目说明与事实状态 `README.md`
- 脱敏交接 `docs/status-and-handoff.md`
- Python 辅助构建/修补/核查脚本（`tools/*.py`）
- 公开仓库敏感文件阻拦配置与语法 CI

未备份（请在受控服务器或另外的**加密备份**中保留）：
- 原始 98K APK、反编译产物、原始 PC 客户端、服务端 EXE、原始 `libgame.so`、地图/怪物/脚本资源
- 用户及角色数据库、测试账号、鉴权信息、完整服务端日志、玩家客户端日志
- 所有签名私钥、keystore、P12、密码文件、token、密钥
- 大体积构建输出，以及可能包含真实设备身份或协议负载的记录

## 在新工作环境恢复研究

1. `git clone https://github.com/lgf921375/98k-repair-private.git`。
2. 阅读 `README.md`、`docs/status-and-handoff.md`，先确认失败与未覆盖状态，不默认 APK 已修好。
3. 单独从经授权的安全存储取得原始程序与必要输入；**不要从公共仓库尝试恢复本就未上传的二进制**。
4. 在隔离环境核对原文件 SHA256、源码路径依赖、资源限制、测试数据边界；正式账号数据库必须另外保护。
5. `tools` 为历史实验脚本，内含绝对路径和受控环境约定，运行前必须人工审查；禁止直接对正式服执行。
6. 使用 `git log` 和 Actions 语法检查确认本仓库的文档/脚本提交成功，**Actions 语法通过不等于 APK 编译、认证或入图通过**。
