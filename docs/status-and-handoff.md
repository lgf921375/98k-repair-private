# 98K Android 修复交接（公开脱敏版）

最后依据：2026-10-17 的只读核查；公开文档不等于最新运行状态承诺。

## 目标与约束
- 解决原安卓客户端选择角色后进地图失败、黑屏、服务端返回 528 的问题。
- 不重置原玩家数据，不改原怪物、地图或用户角色规则。
- 未经证据证明不放宽认证；隔离测试不代表正式服务部署。
- 当前公开仓库仅为研究、交接及辅助脚本镜像，不包含完整原生工程、游戏二进制、签名材料。

## 已知事实（通过）
1. 原候选 APK 包名 `com.gom.asp2`，版本号 `1.0.8`，仅 `armeabi-v7a`。APK 重打包、对齐、CRC 和历史 v2/v3 签名校验完成；这只证明包体技术完整，不证明游戏可玩。
2. 2026-10-16 晚间安卓真机测试的 `RunLogin` 已为 6 段，字段长度依次 `[7,8,1,9,1,32]`，末段 HWID 非空。
3. 同次观察中，`RunLogin` 的账号与服务端 admission 账号匹配，session 相同，并观察到 admission 先于 `RunLogin`。
4. 原 M2 静态反汇编：`GetCertification` 需要账号、角色名和 HWID 非空，解析得到的 session 数值必须至少为 2；这是程序判断，不是已经确认该条件在真实手机上失败。
5. 原 `LoginSrv` 的 session 生成函数会使全局计数器递增并返回；达到上限才回绕为 2。未核实启动时全局初值。
6. 原 PC 客户端历史上曾在隔离服务环境完成账号登录、创角、进地图及单步移动，但后续“精简 PC 自动化版本”不能以该历史结论代替。

## 仍然失败
- 补齐 HWID 的安卓 APK 在真实手机仍收到服务器 `528`，未进地图。
- 精简 PC 自动选服：旧脚本按钮坐标错误，修正后仍停留选服“加载中”；本项测试未通过。

## 未覆盖 / 不能推断
- 真实手机 session **具体数值**：诊断仅记录数字字符串长度为 1，不能据此推出数值是 0 或 1。
- M2 当次 `GetCertification`、`GetAdmission` 的具体失败分支动态命中。
- `525` 后续流程、7210 游戏网关的完整入图确认、地图移动、重登存档。
- 持续运行、万人在线及容量目标。

## 复测优先级（不盲目重装 APK）
1. 在隔离合法认证会话中只记录不含隐私的 `session >= 2` 布尔值、是否匹配 admission 和失败分支类别。
2. 如确认 session 不合规范，追溯原生成器及客户端字段解析；先提供证据与最小改动设计。
3. 如确认 session 符合规范，继续排查 M2 的其他校验及 525/528 状态，不伪造 session、不跳过认证。
4. 选择真实客户端或者可复现协议时序的合法测试器，在已隔离且得到授权的服务中进行回归，最终仍须真机进地图验证。
5. 每轮将“通过／失败／未覆盖”分别记录，保留旧证据，禁止用静态扫描冒充动态验证。
